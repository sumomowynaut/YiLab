# 许可风险分析（Licensing）

> **声明**：本文是工程层面的风险识别，**不构成法律意见**。是否可按某种方式分发、是否需要额外授权，应由项目所有者/法务基于完整许可文本与分发方式作出决定。本文只陈述已核实的事实与需要决策的问题。

## 1. 已核实的事实

| 组件 | 许可 | 来源 |
|------|------|------|
| Pikafish 引擎代码 | GPL v3 | 官方仓库 README / Copying.txt / 官方 Wiki |
| Pikafish 默认 NNUE 权重（pikafish.nnue） | 独立 `NNUE-License.txt`，**非 GPL** | 官方仓库 README / xqbase 整理文本 |
| 官方仓库额外说明 | 部分为 Fairy-Stockfish 象棋变体训练的权重以 CC0 发布 | 仓库 Networks/说明页 |

### 1.1 GPL v3（引擎代码）要点（事实复述）

- 分发须包含许可与（生成确切二进制的）完整源代码，或提供可获取来源的链接。
- 对源代码的修改也须以 GPL v3 提供。

### 1.2 NNUE 权重许可（pikafish.nnue）要点（事实复述）

以任何方式使用权重数据视为同意该许可。已见条款：

1. 仅限合法使用，超出合法范围使用（如网络作弊）的后果由用户自行承担；
2. **未经许可不得用于商业用途**。

> 关键差异：引擎代码 GPL v3 允许商用分发，但**默认 NNUE 权重的许可对商业用途设限**。这是本项目分发决策中的核心风险点。

## 2. 风险清单（仅风险，不判对错）

### 风险 A：捆绑「Pikafish 引擎 + 默认 pikafish.nnue」分发

- 引擎侧：满足 GPL v3 义务（提供源码 + 保留许可）。
- 权重侧：默认权重「未经许可不得用于商业用途」——若项目未来走商业化或进入应用商店付费/含广告等分发，可能受限。
- 开源免费分发：GPL v3 义务明确；权重非商用条款对「非商业开源分发」的适用性需由所有者对照完整许可文本确认。

### 风险 B：不捆绑引擎/权重，由用户自备

- 规避了直接分发 Pikafish 与 NNUE 权重的许可问题（引擎文件由用户放置）。
- 代价：开箱体验下降（需用户自行下载引擎），与「本地优先、开箱即用」目标冲突。

### 风险 C：捆绑引擎 + 使用 CC0 权重

- 官方说明称存在 CC0 授权的（Fairy-Stockfish 象棋变体）权重，可规避默认权重的非商用条款。
- 需确认：CC0 权重的棋力与兼容性、其与所选 Pikafish 版本的匹配、以及来源的真实与权威性（`NEEDS_VERIFICATION`）。

### 风险 D：本项目自身许可证选择

- 若捆绑 GPL v3 的 Pikafish 二进制，本项目整体分发可能需按 GPL 兼容方式处理（GPL 传染性）。选择 MIT/Apache 还是 GPL，**必须由项目所有者决定**，并考虑是否捆绑 Pikafish。
- 不捆绑引擎时，本项目 UI 与 Rust Core 可独立选择更宽松许可。

### 风险 E：第三方组件

- Tauri（MIT/Apache-2.0）、React（MIT）、SQLite（公有领域）、shadcn/ui（MIT）、Zustand（MIT）等，常规可商用，需在发布时附 NOTICE。此处仅登记，不做逐项深挖。
- 若引入 OCR 本地模型权重，其许可须在选型时纳入本清单（见 `docs/ocr.md`）。

### 风险 F：XQF / 东萍 等格式

- 格式本身一般为公开可解析的文件格式；本项目自行实现解析不涉及复制其实现代码。但若为兼容而引入某软件的非开源解析库，需单独核对其许可。`NEEDS_VERIFICATION`：确认不依赖受限的第三方解析实现。

## 3. 发布前必须完成的决策（Action Items）

1. 确认默认 NNUE 权重完整许可文本原文（以官方仓库 `NNUE-License.txt` 为准），明确「非商用」条款边界。
2. 决定分发形态：捆绑引擎+权重 / 仅捆绑引擎 / 用户自备（三选一）。
3. 若走捆绑，决定权重来源：默认 pikafish.nnue 或 CC0 替代权重（并验证棋力与版本匹配）。
4. 决定本项目许可证（GPL v3 或宽松许可），并据此确定是否捆绑 Pikafish。
5. 在首次公开 Release 前，由所有者/法务完成最终确认；在确认前，`STATUS.md` 与 `development-plan.md` 将该事项标为 Blocked（仅针对 Release 阶段，不阻塞开发）。

## 4. 结论

本项目**开发阶段不阻塞**（本地开发与测试可使用引擎与权重）。但**公开分发/Release 阶段被许可决策阻塞**：需先完成 §3 的决策，才能产出合规的 Windows 安装包与便携版。
