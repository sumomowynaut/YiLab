# 导入导出架构（Import / Export）

## 1. 总体架构

格式无关的内部模型（`game-model.md` 的 GameTree + FEN）与各格式适配器解耦：

```
Rust 内部模型（GameTree / Position / FEN）
        ▲                    │
        │ Parser             │ Serializer
        │                    ▼
┌───────┴────────────────────────┴───────┐
│   Import/Export trait（io 模块）          │
│   parse(bytes) -> GameTree             │
│   serialize(GameTree) -> bytes         │
└──────┬─────┬─────┬─────┬─────┬─────────┘
       │     │     │     │     │
     FEN   PGN   XQF   TXT  东萍
```

```rust
pub trait Codec {
    /// 支持的格式标识
    fn format(&self) -> Format;
    /// 从字节解析（UTF-8 文本或二进制），返回带元数据/变例/注释的棋谱树
    fn parse(&self, bytes: &[u8]) -> Result<GameTree, ImportError>;
    /// 序列化为目标格式
    fn serialize(&self, tree: &GameTree) -> Result<Vec<u8>, ExportError>;
}
```

- 每个格式一个实现；新增格式只需新增一个 `Codec`，不触碰核心。
- 错误必须可定位（行号/字节偏移 + 原因），供 UI 显示「第 N 步无法解析」。

## 2. 格式能力矩阵

| 格式 | 导入 | 导出 | 保留变例 | 保留注释 | 状态 |
|------|:----:|:----:|:--------:|:--------:|------|
| FEN | ✅ | ✅ | ❌（单局面） | ❌ | 已确认 |
| PGN | ✅ | ✅ | ✅（依赖方言） | ✅ | 已确认（方言待定） |
| XQF | ✅ | ✅ | ✅ | ✅ | 字段待确认 |
| TXT（中文纵线制文本） | ✅ | ✅ | ❌（线性） | 部分 | 方言待确认 |
| 东萍棋谱 | ✅ | ✅ | ✅ | ✅ | 语法待确认 |

## 3. 各格式规格

### 3.1 FEN

- 仅表达**单个局面**，非整盘棋谱。用于：复制局面、局面链接、导入单局面、开局库检索。
- 规格见 `game-model.md` §6。
- 实现：`FenCodec` 同时负责 `Position <-> String`，是其他格式的基础。

### 3.2 PGN

- 中国象棋 PGN：国象 PGN 的象棋方言（起始局面用象棋 FEN，走法用 UCI-Cyclone 或中式记谱）。
- 导入：解析 tag pairs（`[Event "..."]`）+ 走法 + `{}` 注释 + `()` 变例（`(1. ... Nc3)`） + NAG（`?!`）。
- 导出：生成含 header + 主线 + 变例的 PGN 文本。
- **方言**：中国象棋 PGN 尚无唯一权威标准，走法记谱方式（UCI vs 中文纵线制）需选定并保持一致。`NEEDS_VERIFICATION`：确定兼容主流象棋软件（如象棋巫师、鲨鱼界面）的 PGN 方言。

### 3.3 XQF

- 二进制棋谱格式，国内打谱软件事实标准（网页版下载即 XQF）。
- 已知（常识级）：有文件头 + 对局信息 + 走法编码 + 注释区，支持变例与注释。
- **权威字段级规格未在本仓库确认**。`NEEDS_VERIFICATION`：XQF 头结构、走法编码、变例/注释偏移的权威定义来源。
- 实现策略：先做**导出**（供网页版/其他软件互认的保底能力），再做导入；解析器需大量样本做往返测试（见 `testing.md`）。

### 3.4 TXT（中文文本棋谱）

- 线性文本棋谱，常见「纵线制」记法（红方用中文数字、黑方用阿拉伯数字；进/退/平）。示例：`1. 炮二平五 马8进7`。
- 特点：通常无变例、注释能力弱、且「纵线制」依赖红黑视角换算（红方列从右向左、黑方从左向右）。
- 首版支持「导入线性棋谱 + 导出主线」，变例/注释导出时丢弃或另存说明。
- `NEEDS_VERIFICATION`：纵线制 ↔ UCI 坐标换算的边界（炮/马/兵的「进/退」歧义消解）需样本验证。

### 3.5 东萍棋谱

- 文本格式，支持变例与注释（网页版「复制东萍棋谱」明确支持变招）。
- 是网页版与国内用户间常用交换格式。
- `NEEDS_VERIFICATION`：东萍格式完整语法（变例嵌套、注释定界符、元数据头）。

## 4. 导入导出入口（产品功能）

对齐网页版基线（见 `product-spec.md`）：

- 文件上传导入：自动识别扩展名（`.pgn`/`.xqf`/`.txt`/`.dp` 等），扩展名不可靠时按内容嗅探。
- 粘贴导入：FEN 或文本棋谱。
- 复制：FEN / 文字棋谱 / 东萍棋谱。
- 下载：XQF。
- GIF：见 `feature-matrix.md`（属导出，但走独立渲染管线，见 UI 层）。

## 5. 往返一致性

- 每种支持「往返」的格式（PGN/XQF/东萍）必须满足：`parse(serialize(tree))` 在主线 + 变例 + 注释层面语义等价。
- FEN 满足 `parse(serialize(pos)) == pos`。
- 等价性作为集成测试的黄金文件基线（见 `testing.md`）。
